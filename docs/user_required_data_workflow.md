# USER_REQUIRED 项目补资料流程

1. 在项目工作区的数据导航打开“项目实测数据”。
2. 查看每项缺失资料、被阻塞能力和数据原因；公开数据候选不会覆盖 USER_REQUIRED。
3. 下载当前补资料包或所需 MR01–MR06 模板，仅填写有证据支持的内容。未知量留空；不要用 0 代替缺失值。
4. 上传 CSV/XLSX 后先检查校验结果、行列定位和预览。错误文件可修订后重新提交；原提交不会覆盖。
5. 对需要判断的坐标系、受纳水体/河段和审批参数，由本地审核人填写理由后确认。系统不会依据最近距离或名称相似度自动绑定。
6. 只有明确审核接受的数据会写入项目数据登记、血缘和新项目版本；拒绝或待确认数据不会进入模型输入。
7. 接受后自动重跑现有 requirement resolver 并记录状态变化。任何门禁仍由既有规则计算，界面不提供人工设为 ready 的入口。

## 六类资料

| 编号 | 内容 | 关键约束 |
|---|---|---|
| MR01 | 排口基础与坐标 | 明确坐标来源与 CRS；GCJ-02/BD-09 不伪装为 WGS84 |
| MR02 | 排口实际水量 | 区分实测/报送实际、估算、设计能力和许可上限；只有实际语义可进入实测流量候选 |
| MR03 | 污染物监测 | source、污染物、采样时间和单位必须明确；`<检出限`保留限定符 |
| MR04 | 受纳水体/河段 | 要有关系证据和人工确认；nearest reach 不是确认 |
| MR05 | 污水设施运行 | 需记录设施、明确时间、实际水量和运行状态 |
| MR06 | 项目系数审批 | 复用 M9A.1 factor approval，并保留审核人和理由 |

流量与浓度必须同源且时间期段匹配才会显示实测负荷候选；不同日期或缺少时间不会被合并。测量数据只表明证据可供现有规则评估，不代表全流域核算完成，也不触发 M9B。

## 输出与排障

项目级原件、审查记录、标准化副本和 lineage 均存于项目工作区；汇总报告写到 `output/measurement_intake/m10a/`。若项目卷未挂载，先恢复原 workspace 存储，不要把数据复制到仓库 `data_raw/`。宏工作簿、`.xlsm`、外部链接工作簿和超过 50 MiB 的文件不接受。系统没有账号服务，请勿把敏感个人信息放入 reviewer 字段或意见。
